# 글 검토와 다이어그램

글을 다듬거나 그림을 만들 때의 기준입니다. 파일을 다루는 절차는 [content-workflow.md](content-workflow.md)를 참고하세요.

## 글 검토

- **사실 대조:** 코드가 근거인 내용은 실제 코드로, 일반적인 사실은 공식 문서로 확인합니다. 확인하지 못한 추론은 따로 표시해 사용자에게 알립니다.
- **문체 유지:** 작성자의 문체(합니다체, 가끔 해요체)를 지키고 문장을 새로 쓰기보다 다듬습니다.
- **비공개 정보:** 회사 저장소 URL·커밋·내부 이름처럼 공개되면 안 되는 정보는 넣지 않습니다. 필요하면 `<fork>`처럼 자리표시로 둡니다.
- **구조:** 도입부가 문제와 범위를 보여주는지, 마무리(요약·회고·남은 과제)가 있는지, 제목이 다루는 범위와 맞는지 봅니다.
- **진행 방식:** 고칠 곳과 근거를 먼저 제안하고, 승인받은 범위만 적용합니다.

### 서식

- **인라인 코드:** 코드에 그대로 쓰이는 이름(클래스, 위젯, 속성, 설정, 메서드, 패키지, CSS 속성·변수)에만 씁니다. 개념·제품 이름(웹뷰, Flutter, WebKit)은 그대로 둡니다. 코드 블록, 제목, 링크 주소는 건드리지 않습니다.
- **볼드:** 섹션마다 핵심 주장 한두 개에만 씁니다.
- **링크:** 독자가 찾아볼 공식 문서에만, 처음 나올 때 한 번 겁니다. 주소와 `#앵커`가 실제로 열리는지 확인합니다. 인라인 코드에 걸 때는 `` [`name`](url) ``처럼 코드 모양을 유지합니다.

## 다이어그램

- 공간 배치가 중요한 그림(폰 화면, 레이어)은 PNG로, 흐름 위주인 그림은 코드 블록 안의 ASCII로 그립니다.

### PNG

- 템플릿은 [`scripts/diagrams/`](../scripts/diagrams/)에 있습니다. `base.css`(블로그 팔레트와 폰 목업)를 쓰고, `examples/`를 참고해 HTML을 만듭니다.
- `node scripts/diagrams/render.mjs <file.html>`로 같은 이름의 PNG(2배 해상도)를 만듭니다.
- 목업 안의 선은 프레임 곡선을 따르게 모서리 반경을 맞추고, 라벨과 선이 겹치지 않게 합니다.
- 화면 밖이나 키보드 뒤에 있는 영역은 흐린 선으로 이어 박스가 끊겨 보이지 않게 합니다.
- 같은 괄호에 서로 다른 값을 함께 묶지 않습니다.
- 오른쪽 아래에 `Illustrated by Claude`를 작게(`.credit`) 넣습니다.

### ASCII

- 정렬이 필요한 줄에는 한글을 쓰지 않습니다(폭이 달라 어긋남). 한글 설명은 줄 끝에만 둡니다.
- 렌더링 후 세로 기호들이 같은 열에 있는지 확인합니다.
